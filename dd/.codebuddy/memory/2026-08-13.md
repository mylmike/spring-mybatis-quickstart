- 明细表新增合计行：`displayList` computed = [合计行, ...sorted]，合计所有数字列（预算合计/实际合计/合计差异/实际·预算·差异各月）。合计行 `_isSummary` 标记 + `summary-row` 高亮，固定在表格第一行，不参与排序。排序改为 `sortable="custom"` + `@sort-change` 手动排序（`getSortVal` 按 prop 取值，月份预算列走 getBudget），仅排数据行，合计行始终在最前。月份子列已加 prop（实际/预算/差异XX月）。
- 合计行置顶冻结（最终方案：副表头）：CSS sticky / JS transform 方案在 Element Plus 固定列区均失效（transform 不能用于 table-row；固定列内部用 transform 同步滚动）。改为「副表头」：合计行不再放 `:data` 里，`:data="sorted"` 只含明细；在 el-table 上方渲染 `.sum-strip` 绝对定位条（`top = 表头高度`），分左固定区（7 列）+ 右滚动区（36 个月份列，ref=sumScrollRef），横向滚动时右区 `translateX(-scrollLeft)` 跟随。列宽从 `.el-table__body-wrapper colgroup col` 的 offsetWidth 实时同步（前 7 / 后 36），表头高度读 `.el-table__header-wrapper`，行高读第一行 `.el-table__row`，用 ResizeObserver 监听 el-table 尺寸变化，onMounted/onUpdated 时 refreshStrip。合计值 `sumRow` computed 基于 `list.value` 累加（不受排序影响）。
- 用户反馈副表头方案也失败（应为列宽对齐/效果问题），已**回退到最初方案**：合计行作为数据行第一行（`displayList` computed = [合计行, ...sorted]），`:data="displayList"`，`summary-row` 高亮，不冻结（随滚动）。当前 BudgetReport.vue 保持此状态，合计行冻结功能放弃。
