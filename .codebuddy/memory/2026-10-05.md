# 2026-10-05 工作日志

## queryUnfinishedOrders 增加返回值 wpsl（订单未排数量）
- 需求：`/queryUnfinishedOrders` 返回加 `wpsl = sfaguc003 - sfaguc004`（订单未排数量）。
- 实现：`OrderSqlProvider.queryUnfinishedOrders` 内层 SQL 增加
  `LEFT OUTER JOIN sfaguc_t on sfagucent = xmddent and sfagucsite = xmddsite and sfaguc002 = xmdddocno and sfaguc005 = xmddseq`
  以及 `SELECT (NVL(sfaguc003,0) - NVL(sfaguc004,0)) wpsl`。
- `IndexController.queryUnfinishedOrders` 中 `item.set("wpsl", ...)` 输出该字段。
- 说明：wpsl 用 SQL 计算（sfaguc003 需求总数 - sfaguc004 供给总数），未匹配 sfaguc_t 时 NVL 取 0 → wpsl=0。无需 Java 额外计算，依赖前序 sfaguc_t 的写入（queryOrderBom/saveSfahuc）。
- 部署：改了 Java（Provider 是 SQL 拼串，也需重打包），须 `mvn clean package -DskipTests`(JDK17) 重新打包 war。数据库 sfaguc_t 表此前已存在。

## saveSfahuc 保存前校验「排程数量不超订单需求数量」
- 规则：`sfahuc011`(订单需求数量) - 累计`sfahuc016`(排程数量) < 0 则保存报错（success=false + message），不落库。
- 分组键（五字段合计）：`sfahucent` + `sfahucsite` + `sfahuc004`(订单号) + `sfahuc005`(订单序号) + `sfahuc002`(品号)。
- 实现：`SfahucMapper.sumScheduleQtyByOrderItem`（新增，含 sfahuc002）；`IndexController.saveSfahuc` 在保存循环前做预校验——先算本次请求各分组新排程量合计、各主键旧量，再 `dbSum - 本次涉及主键旧量合计 + 本次新量合计` 得最终累计，与 sfahuc011 比较。
- 注意：sfahuc004/sfahuc005/sfahuc011 任一为空则跳过该校验（无法成组/无订单需求值）。单次请求含同分组多工单时整体纳入，避免重复计数。
- wpsl 默认调整：`queryUnfinishedOrders` 中 `NVL(sfaguc003,0)` 改为 `NVL(sfaguc003,xmdd006)`（未匹配 sfaguc_t 时取订单量）。
- 部署：改 Java，须重新打包 war（JDK17）。
