## 2026-08-11

### 修复预算与实际差异明细表 ORA-00942
- 问题：glaq_t / glap_t / glacl_t / ooefl_t / bgbsuc_t 均在 dsdata（second 数据源）中，错误放在 primary 数据源执行导致 ORA-00942
- 解决：
  - 删除 primary/GlapMapper.java、primary/GlapSqlProvider.java
  - BudgetActualSqlProvider 改为构建完整单条 SQL：实际费用 LEFT JOIN 预算结存，含 12 个月差异、预算合计、实际合计
  - DsdataMapper 改为 `queryBudgetActualVariance` 单方法
  - IndexController 改为直接调用 DsdataMapper 单查询，返回前统一列名（差异1月→差异01月，预算合计金额→预算合计等）

### 修复 ORA-00904: "月": invalid identifier（两次）
- 第一次：预算/实际合计金额表达式前缺少逗号，导致列名拼接错误
- 第二次（根本原因）：实际费用内层 SELECT 只写了 `年, 月` 没有 EXTRACT 表达式，Oracle 把它们当成未知列名。修改为 `EXTRACT(YEAR FROM glapdocdt) 年, EXTRACT(MONTH FROM glapdocdt) 月`，GROUP BY 同步修改

### 修复返回缺少预算/差异字段
- 根因：LEFT JOIN 未匹配时 ys 侧为 NULL，Hutool JSONObject 默认忽略 null 值导致预算/差异字段丢失
- 解决：SQL 外层预算/差异/合计列加 NVL(..., 0)；Controller 数值列 null 时输出 0

### 差异公式调整
- 用户明确要求：差异 = 实际 - 预算（原为预算 - 实际），1~12 月统一，已修改 SQL Provider

### 返回字段名调整
- 用户明确要求：所有 "本年" 字样替换为 "实际"（实际01月~12月），SQL Provider 内层别名/外层引用/合计/差异及 Controller null 判断同步修改
